# MultiTimer: короткий план перевірки

Запит «перевір додаток» означає BASIC, без нового планування. Це базова перевірка некритичного додатка. Обсяг і м'який бюджет витрат: [AGENTS.md](AGENTS.md).

## BASIC

1. Перевірити робочі зміни й останній результат. Для загальної перевірки вибрати всі рядки, для зміни коду лише пов'язані. Не запускати тести перед редагуванням, крім потрібного відтворення помилки.
2. Виконати три команди нижче один раз. Наявні 37 тестів виконуються одним набором; A01-A08 описують його покриття, це не додаткові запуски.
3. Одноразово оглянути код за C01-C08: максимум 8 цільових читань/пошуків, із групуванням пов'язаних функцій. Неперевірене позначати, не розширювати пошук.
4. Записати результат і завершити. Максимум один повторний раунд лише невдалих/змінених перевірок. Звичайний запит перевірки не включає виправлення.

```powershell
.\deno.exe check src/app.js
.\deno.exe lint src/app.js tests/
.\deno.exe test --allow-read=src/app.js,index.html tests/app-state.test.js
```

Якщо локального Deno немає, використати `deno` з PATH; якщо немає обох, зазначити блокування без встановлення. Виводити підсумок і помилки, не весь успішний журнал. Використовувати наявні підміни часу/відмов, не чекати годинами й не змінювати системний годинник.

## Фіксований каталог

Кожен рядок один раз. A = наявні автотести; C = огляд коду, не інтерактивний тест. Послідовність C є одним сценарієм, без перебору додаткових комбінацій. Спільний код не перечитувати.

| ID | Функція / сценарій | Очікування / орієнтир |
| --- | --- | --- |
| A01 | Відновлення «Гра» / «Чай 8», обраного, порядку, паузи; старі поля браузера | Сталі ID, правильні назви/цілі; чужі поля не перезаписують стан. |
| A02 | Некоректні збережені ID, timestamps, відсутні поля будильника | Нормалізація без падіння рядків. |
| A03 | Тривалість, дробова секунда, дати, `24:00`, наступний день | Наявні граничні приклади; нуль не передчасний, неможливі дати відхиляються. |
| A04 | Автосортування, пауза, обране; перейменування | Збережені ID/стани; пауза сортується за замороженим залишком. |
| A05 | Favicon і статичні переклади UA/EN | Чотири стани, врахування паузи/деактивації, повнота ключів. |
| A06 | Mute, гучність, тест звуку, два сигнали, відмова аудіо | Припинення/звільнення звуку; збій не блокує збереження завершення. |
| A07 | Worker, резервний таймер, довгий строк | Одне сповіщення на дедлайн, перепланування, звільнення ресурсів після відмови. |
| A08 | Стрибок часу, повторна обробка завершення | Актуальний залишок; одна обробка кожної цілі. |
| C01 | Створення → відлік → завершення → скидання тривалості | `createTimerFromForm`, `updateTimers`, `resetDurationTimer`: правильна ціль, потім `+час`, скидання до «Задано». |
| C02 | Пауза → продовження тривалості | `pauseTimer`, `resumeTimer`, `updateTimerRow`: залишок стоїть, «Ціль» = прочерк, «Задано» незмінне; нова ціль = зараз + залишок. |
| C03 | Продовження будильника до цілі; після цілі (2 гілки) | `resumeTargetTimer`, `rescheduleTargetTimerNextDay`: початкова ціль або найближчий майбутній день із тим самим часом; «Задано» незмінне. |
| C04 | Деактивація → пауза → продовження → активація | `toggleDeactivated`, `getRemainingMs`: незалежність деактивації й відліку, включно з простроченням. Індикацію/звук не дублювати, див. A05-A07. |
| C05 | Діалог: змінити час, скасувати; видалити один; очистити всі | `saveEditFromDialog`, `closeEditDialog`, `deleteTimer`, обробники: кожна дія один раз; скасування не зберігає, очищення з підтвердженням, правильний ID. |
| C06 | Налаштування та ручний порядок | `updateSetting`, обробники панелі, `moveTimerBefore`: по одному простеженню збереження мови/рингтона/тривалості/порога, напрямку/ручного сортування й перетягування; деактивовані позиції не пересортовуються. |
| C07 | Недоступне сховище; відмовлений дозвіл сповіщень (2 гілки) | `loadState`, `saveState`, `toggleDesktopNotifications`, `notifyTimerExpired`: обробка помилок і чесність індикації. Відсутність падіння не доводить збереження. |
| C08 | Застарілий/мертвий код: один пошук визначень і посилань | JS/HTML/CSS: невикористані символи, дублікати, від'єднані обробники/селектори. Врахувати шаблони, Worker і динамічні класи; одиничне входження не доводить зайвість. Без автоматичного видалення. |

BASIC = 3 команди, 37 тестів один раз, 8 пунктів огляду коду. Після зміни коду: три команди й лише зачеплені C-пункти. Документація без зміни поведінки: тільки посилання й різниця файлів, без тестів додатка.

## UI: лише за потреби

Для змін вигляду/взаємодії або явного запиту UI-перевірки: рівно два огляди, UA 1280×800 та EN 390×844, масштаб 100%. В окремому тестовому профілі відкрити `index.html`, один раз прокрутити список і відкрити діалог на кожному розмірі. Обидва блоки керування доступні, значення/кнопки не перекриті. Змінену взаємодію виконати один раз. До двох скриншотів; додатковий лише для знайденої помилки.

Основне середовище: Firefox / Windows / `file://`. Інший браузер не видавати за Firefox. За відсутності UI-інструментів зазначити пропуск, не будувати новий стенд.

`tests/browser-smoke.js` із README є РОЗШИРЕНОЮ перевіркою: один запуск лише за окремим запитом. Він використовує Chromium, UA/EN і шість ширин; не дублювати короткий UI-прохід без причини. BASIC не включає нічні прогони, навантаження, фізичний reset, ігри/програвачі чи перебір браузерів. Підміни тестів не підтверджують фізичний звук або системне сповіщення. Не гарантувати сигнал при вивантаженні вкладки чи сні ОС.

## Оновлення та результат

При зміні поведінки уточнити відповідний рядок; новий додавати лише для нової функції. Пов'язаний тест додавати до наявного набору, актуалізувати кількість тут і в README. Не створювати нової матриці для кожного виправлення.

Після перевірки замінити запис нижче, без накопичення журналу: дата, середовище, commit, відбитки, виконані ID/спосіб, кількість успіхів/помилок/пропусків, короткі проблеми. Відбитки: `git hash-object src/app.js index.html styles.css tests/app-state.test.js tests/browser-smoke.js` (у цьому порядку). Повторно використовувати результат лише за однакових відбитків, середовища й обсягу; інакше зачеплені результати застарілі. Огляд позначати «оглянуто», не «тест пройдено».

- `check`: успішно; `lint`: успішно (3 файли); A01-A08: 37 тестів пройдено, 0 помилок, 0 пропусків. Повторних запусків не було.
- C01-C08: оглянуто один раз у межах зазначених ділянок; 1 зауваження (C07), в інших пунктах явних проблем не виявлено. C08: серед 103 визначень функцій немає одиничних входжень; CSS-класи мають текстові посилання в JS/HTML. Це базовий пошук, не доказ відсутності всього мертвого коду.
